# WebUI 使用说明

## 一键启动

双击：

```text
<v1.0 所在路径>\start.bat
```

脚本会检查端口、按需启动项目自带 Ollama，然后启动 WebUI 并打开浏览器。

## 手动启动

## 启动顺序

1. 先手动启动项目自带 Ollama。

```powershell
cd <v1.0 所在路径>
$env:OLLAMA_MODELS = "$PWD\models\ollama"
$env:OLLAMA_LIBRARY_PATH = "$PWD\runtime\ollama\lib\ollama"
$env:OLLAMA_HOST = "127.0.0.1:11434"
$env:OLLAMA_MAX_LOADED_MODELS = "1"
$env:OLLAMA_NUM_PARALLEL = "1"
& "$PWD\runtime\ollama\ollama.exe" serve
```

2. 再打开另一个 PowerShell 启动 WebUI。

```powershell
cd <v1.0 所在路径>
.\runtime\python\python.exe .\webui\app.py
```

浏览器会打开：

```text
http://127.0.0.1:8765
```

## 安全边界

- WebUI 只监听 `127.0.0.1`，局域网和互联网设备无法访问；
- 不上传文献到云端；
- 不自动下载模型；
- 不自动启动 Ollama；
- 不使用外部前端依赖，HTML、CSS 和 JavaScript 全部保存在本地；
- 上传大小上限为 300MB；
- 最终文件保存在 `data\output\原文件名__内容哈希\`；
- 同一个输入文件始终使用同一个输出文件夹；
- `data\jobs` 只作为临时处理缓存，可以由 WebUI 清理。

## 当前功能

- 拖拽或选择 PDF；
- 查看处理阶段与实时日志；
- 翻译过程中按块更新进度；
- 自动跳过纯数字、符号和坐标轴标签，避免无效翻译和失败；
- 扫描版 PDF 自动 OCR（Windows 自带识别引擎，离线可用），日志中会显示识别进度；
- 下载中文 PDF；
- 下载中英对照 PDF；
- 下载总结、术语表和质检报告；
- 查看最近任务记录；
- 清理临时缓存，不删除 output 最终结果。

## 扫描版 PDF

上传没有文字层的扫描件时：

1. 日志出现“未检测到文字层，改用 OCR 识别扫描页面”；
2. 逐页显示“渲染第 N/M 页”和“OCR 识别 M 页”；
3. 提取完成后显示识别出的文字行数量；
4. 译文按阅读顺序重新排版为中文页面；中英对照版把原扫描页和译文上下并排。

如果 OCR 关闭、系统缺少识别语言包，或页面数超过 `configs/ocr.json` 中的
`max_pages`，任务会直接失败并给出原因，不会输出一份未翻译的原文件。

### OCR 会先把行合并成段落

识别引擎是逐行输出的，合并成段落后再翻译，译文才连贯：

- 段内换行会按行距、缩进和行宽自动合并；
- 期刊在行尾的软连字符会被接回（`eﬃ` + `cacy` → `eﬃcacy`）；
- 普通单词之间永远不会被硬粘在一起。

一份 2 页扫描论文的实测改善：

| 指标 | 逐行版本 | 段落版本 |
|---|---|---|
| 提取内容块 | 128 | 50 |
| 待翻译内容块 | 93 | 27 |
| 锁定术语 | 0 | 25 |

### 已知局限：跨栏行

部分医学期刊是双栏排版，识别引擎可能把**左栏某行的后半句**和**右栏同一行的后半句**
当成一行。这种交错文本在翻译前无法完全拆开，实测表现是：大部分段落正常，
但个别内容块会出现两句交错，质检会因此拦截整个文档。

遇到这种情况：

- 查看 `qa_report.json` 中失败的 `block_id`，确认是否属于交错行；
- 这类块交给人工校对，或改用带文字层的原始 PDF（提取页面时不要用“打印成 PDF”）。

段落合并与栏内行距的判断是可靠的；跨栏拆分的阈值在这类排版上无法稳定区分
“栏间距”和“行内大间隙”，因此没有启用激进的切分，避免把正常句子切碎。
